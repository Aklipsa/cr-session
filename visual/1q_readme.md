# Трёхсторонний протокол распределения ключей — интерактивная визуализация

Учебная интерактивная схема протокола распределения сеансовых ключей с участием
доверенного центра (KDC). Реализована как одиночный HTML-файл без зависимостей:
открывается в любом современном браузере, сборка и сервер не нужны.

## Запуск

1. Сохраните файл `key_distribution_protocol_test.html` (кодировка UTF-8).
2. Откройте его двойным кликом в браузере (Chrome, Firefox, Edge, Safari).

Интернет не требуется: все стили, скрипты и данные встроены в файл.

## Что демонстрируется

Трёхсторонний протокол установления сеансового ключа между участниками **A**
(инициатор) и **B** (ответчик) при посредничестве доверенного центра **T** (KDC):

| Шаг | Маршрут | Сообщение | Смысл |
|-----|---------|-----------|-------|
| 1 | A → T | `ID_A, ID_B, n_A` | запрос сеансового ключа, nonce `n_A` против повтора |
| 2 | T → A | `E(K_AT; K_AB, ID_A, ID_B, n_A) ‖ E(K_BT; K_AB, ID_A)` | центр генерирует `K_AB`; часть для B — «билет» под его мастер-ключом |
| 3 | A → B | `E(K_BT; K_AB, ID_A)` | A пересылает билет; B расшифровывает его своим `K_BT` |
| 4 | B → A | `E(K_AB; n_B)` | B подтверждает владение ключом свежим nonce |
| 5 | A → B | `E(K_AB; n_B − 1)` | A отвечает на nonce — взаимная аутентификация |

Обозначения: `E(K; M)` — шифрование сообщения `M` на ключе `K`;
`K_AT`, `K_BT`, `K_CT` — долгосрочные мастер-ключи пар «участник–центр»;
`K_AB` — сеансовый ключ; `n_A`, `n_B` — одноразовые числа (nonce).

## Структура страницы

- **Шапка + схема протокола** — карточки участников A, B, T, соединённые
  каналами с двумя встречными стрелками на каждый поток;
- **Шаг протокола** — кнопки управления и подсхема шагов в строку;
- **Роли участников** — краткое описание задач каждой стороны;
- **Трассировка сообщений** — таблица всех передач и итоговый вывод.

## Управление

- **▶ Следующий шаг** — выполняет очередной шаг протокола: на схеме активируется
  стрелка, появляется плашка с формулой сообщения, заполняется таблица;
- **Все шаги** — проигрывает протокол целиком;
- **⟲ Сброс** — возвращает схему, подсхему, таблицу и карточки в начальное состояние.

## Визуальная логика подсветки

- **Синяя обводка/линия** — элемент не участвует в текущем шаге
  (карточка) или шаг уже выполнен (стрелка, переход подсхемы);
- **Зелёная пунктирная стрелка и зелёные карточки** — шаг выполняется
  прямо сейчас: подсвечиваются только его отправитель и получатель;
- **Плашка с номером на стрелке** — формула передаваемого сообщения;
- **Зелёные чипы «знает:»** — появляются, когда участник узнаёт
  сеансовый ключ `K_AB` (шаг 2 — у A, шаг 3 — у B).

Геометрия стрелок пересчитывается автоматически при изменении размера окна:
линии строятся от границ карточек, пары встречных стрелок остаются параллельными,
плашки не перекрывают друг друга и не выходят за пределы сцены.

## Технические детали

- Чистый HTML + CSS + ванильный JavaScript, без фреймворков и сборки;
- Стрелки рисуются в SVG: направление и точки входа/выхода считаются
  пересечением прямой с прямоугольником карточки (slab-метод);
- Палитра и стили согласованы с дизайн-системой компонента ECDH
  (светлая тема, синий `#007bff` / зелёный `#1f9d55`);
- Расположение плашек шагов подбирается автоматически с проверкой
  пересечений по фактическим размерам.

## Ограничения модели

Итоговый блок на странице фиксирует слабость схемы: доверенный центр T —
единая точка доверия и отказа, а компрометация мастер-ключа участника
раскрывает все его сеансы. Развитие темы — протоколы с распределением
доверия (Needham–Schroeder, Kerberos, комбинирование с асимметричной
криптографией).
